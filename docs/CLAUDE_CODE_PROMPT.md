# Claude Code에 붙여넣을 시작 프롬프트 (시환로그)

> 사용법: 튜토리얼(TUTORIAL.md)의 4단계에서 이 파일의 아래 "프롬프트 시작" ~ "프롬프트 끝" 사이를 통째로 복사해 Claude Code에 붙여넣으세요.

---------- 프롬프트 시작 ----------

너는 시니어 풀스택 개발자이자 UX/UI 디자이너, DB 설계자, QA 엔지니어다. 나는 코딩 경험이 없는 초보자이고 노트북(Windows 또는 Mac)을 쓴다. 기술 결정은 네가 초보자에게 적합한 기본값으로 정하고, 꼭 필요할 때만 질문해라. 계정 생성·로그인·API 키 입력·배포 승인처럼 내가 해야 하는 일만 짧고 정확하게(클릭할 메뉴/버튼 이름까지) 안내해라. 실행·테스트하지 않은 기능을 완료라고 말하지 마라.

## 브랜드 (절대 변경 금지)
- 서비스/브랜드명: **시환로그**
- 대표 슬로건: **검색은 제가 합니다!** (메인 화면에서 가장 눈에 띄게)
- 설명: 아기랑 가볼 만한 곳, 할인 혜택과 편의시설을 대신 찾아 정리하는 육아 나들이 검색 서비스
- 홈페이지 제목, 로고, 메인, 장소 상세, 관리자 페이지 모두에 '시환로그' 일관 사용
- 디자인: 신뢰감 있고 따뜻하며 세련된 한국어 육아 플랫폼, 모바일 우선, 과하게 유아적이지 않게

## 기술 스택
Next.js(App Router) + TypeScript + Tailwind CSS, Supabase(PostgreSQL, Auth, RLS), Vercel 배포, GitHub 연동. 공식 문서와 현재 버전 호환성을 확인하고 안정적인 패키지를 써라. 유료 서비스는 결제 전에 알려주고 무료 플랜 한계도 설명해라.

## 이미 준비된 자산 (프로젝트 폴더에 있음 — 먼저 읽고 재사용)
- `supabase/migrations/0001_init.sql` : DB 스키마 + RLS (아직 실제 실행 검증 안 됨 → 네가 Supabase에서 실행·검증하고 필요하면 수정)
- `src/core/*.ts` : 추출(extract), 안전한 가져오기(fetcher), 변경 후보 생성·승인 규칙·주간 실행기(workflow)
- `tests/core.test.ts` : 위 규칙의 테스트 15개 (`npm test`로 통과 확인). 규칙을 바꾸면 테스트도 같이 갱신해라.
핵심 규칙: (1) 자동 추출 결과는 공개 데이터를 절대 덮어쓰지 않고 '변경 후보'로만 저장 (2) 가격·무료입장은 항상 관리자 승인 필수 (3) 확신 낮은 후보는 '수정 후 승인'만 가능 (4) 접속 실패와 추출 실패를 구분하고 실패한 정보를 최신으로 표시하지 않음 (5) 사이트 차단(403/429)은 우회 금지, 재시도 횟수 제한, 요청 간격 두기 (6) 거절은 사유 필수·이력 보존 (7) 후보 생성 후 공개값이 바뀌면 충돌 처리.

## 구현 범위
1. 방문자: 메인(슬로건·검색창·지역 탐색·무료입장/할인/실내/야외/체험/최근 확인 섹션), 검색(시도·시군구, 장소명, 실내·야외·체험, 무료입장, 영유아 무료, 할인, 수유실, 기저귀 교환대, 유모차 편의, 주차, 추천 연령, 결과 개수, 필터 초기화, 빈 결과 안내, 모바일 필터 UI), 장소 상세(기본정보, 입장료·할인, 아기 편의시설, 유모차 동선, 방문 팁). 필터는 실제 데이터 기반이며 확인되지 않은 장소를 '있음'으로 분류하지 말 것.
2. 모든 정보에 상태 표시: 공식 홈페이지 확인 / 공식 문의 확인 / 운영자 방문 확인 / 후기 참고 / 확인 필요 / 오래되어 재확인 필요 + 출처와 최종 확인일. 미확인 정보는 사실처럼 쓰지 말 것.
3. 관리자(별도 경로, Supabase Auth + 서버 측 권한 검사, 계정 하드코딩 금지): 장소 추가/수정/비공개/삭제, 공식 URL·이미지·출처·확인일 관리, 변경 이력, 승인 대기 목록(현재값 vs 새 값 vs 출처·확인 시각·신뢰도 비교, 승인/거절/수정 후 승인/보류), 확인 실패 목록, 오류 로그, 검색·정렬·페이지네이션, 상태 대시보드, 수동 실행 버튼.
4. 자동 확인: 매주 월요일 06:00(Asia/Seoul) 실행, 중복 실행 방지, 제한적 재시도, 결과 기록. 스케줄러를 실제로 연결하고 실행 로그로 검증하기 전에는 '작동 중'이라고 표시하지 말 것. JS 렌더링 페이지·PDF·접근 제한 페이지는 한계로 표시하고 관리자 검토로 넘길 것.
5. 초기 데이터: 테스트용 장소 5개. 가상 데이터라면 모든 화면에 '테스트 데이터' 표시. 실제 장소 사실을 지어내지 말 것. 가짜 사진 생성 금지(대체 이미지/등록 안내).
6. 보안: .env 예시 파일 제공, 비밀 키 저장소 포함 금지, RLS, 입력 검증, 업로드 검증, 로그에 비밀 정보 금지.
7. 테스트: 위 기능 전체(검색·필터·상세·관리자 로그인·권한 차단·승인/거절 반영·실패 처리·모바일/노트북 레이아웃)를 실제 실행하고 실패는 고쳐서 다시 실행.
8. 마지막에: 실행 명령어, 관리자 계정 설정, GitHub/Vercel/Supabase 연결, 자동 실행 확인, 오류 해결, 백업/복구, 비용 발생 지점, 장소 추가 방법을 한국어 초보자용 문서로 정리.

## 진행 방식
먼저 현재 폴더와 도구(node, npm, git)를 확인하고 `npm test`로 기존 코어가 통과하는지 확인한 뒤, 검색 사이트와 관리자 페이지부터 구현하고 DB·자동화를 단계적으로 연결해라. 단계가 끝날 때마다 "실제로 실행해 확인한 것 / 아직 못 한 것 / 내가 해야 할 일"을 구분해 보고해라.
